# Server: session reviews and cost estimates

Part of [Server (`server/agent_server/`)](README.md). The session review (checks, scores, exposure scanning, the AI review) and the price table behind cost estimates.

## Module map

| Area | Modules | Key symbols |
| --- | --- | --- |
| Session reviews | `review.py`, `exposure.py`, `exposure_rules.py`, `review_prompts.py`, `default_review_prompts.yaml` | `report(sessions, chats, session, records, prices)`: a session measured without a model: `_traffic` and `_timeline` from its records, always (`_tier` sorts each model call into `TIERS` by its model's list input price in `prices`, the server's table, against `TIER_INPUT_USD`; no cost means local, or unpriced); `_prompt` (sizes, `_sections`, MCP servers), `_composition`, `_conversation` (threads, steps) and `_tools` (by tool, command, file, error) from `Chats.conversations` and the main chat's newest trace, only where payloads were captured. `CHECKS` are functions of the measurements, each returning a finding (`id`, `area`, `severity` from `SEVERITIES`, `title`, `detail`, `suggestion`, `impact_tokens`); thresholds are the constants at the top; `PENALTIES` and `GRADES` make the score through `_score`, which sets each finding's `penalty`: in a `GROUPS` group (checks that see one cause) the worst costs in full and the rest `GROUP_SHARE` of theirs; `UNSCORED` checks and a `failed-calls` finding that is mostly provider 5xx (`provider_errors`) cost nothing. It returns `score_breakdown`; `area_scores` score each of `AREAS` the same way, and `_session_lines` tells the AI review both. **Security** is apart: `_security` reads every text of the traced threads that the model was sent (non-assistant text, tool-call arguments via `_strings`, tool results, `_system_text`) with `exposure.find` (pattern `DETECTORS` for credentials and PII, with placeholder, entropy, Luhn and mod-97 checks), and `_secret_source` marks tool calls that read a file of secrets (`exposure.sensitive_path`) or dumped the environment and got an answer; `measured["security"]` is None without traced calls, or with the `security_scan` setting (`Settings.security_scan`, `set_security_scan`, `config.checked_security_scan`, names in `defaults.SECURITY_SCANS`; `PUT /api/config/security-scan`, in `config export`) at `off`. `report(..., scan)` takes the level; `review.SCAN_LEVELS` says what each runs (`ScanLevel`: detector `kinds`, the text `limit`, `loose` guessed secrets via `exposure.find(..., loose=True)`, and `replies`, the model's own text). `exposure.redact` always finds loosely. Its checks (`credentials`, `personal-data`, `secret-files`) are in area `SECURITY`, which `_score` skips; `_security_score` sets their penalties (`SECURITY_PENALTIES` plus `SECURITY_EXTRA` an extra item, to `SECURITY_CAPS`) and `SECURITY_GRADES` the grade. **Never keep or return a value found**: an exposure has a masked `preview` (`exposure.masked`) and redacted targets only, and `brief()` runs `exposure.redact` over its text so the reviewing model never gets a secret the session leaked. `exposure.py` imports nothing of the server's. A new check that sees an existing cause from another side joins that group. The AI reviews are a stored setting, `review_prompts` (`Settings.reviews()`, `set_review_prompts`; None means `DEFAULT_PROMPTS`, the rows of `default_review_prompts.yaml`, package data; `/api/config/review-prompts`, `SITE_ADMIN_ONLY`; in `config export`): `review_prompts.checked_prompts` checks a set, `Prompt` is one (its `focus`, the `DATA` names it's sent, the `METRICS` ids whose findings go with it, `instructions()` = `PREAMBLE` + focus + `FORM`). `review_prompts.py` imports nothing of the server's, so `config.py` can import it. `review.SECTIONS` has the function behind every `DATA` name; `brief(session, found, prompt, question)` writes the messages (never the transcript, at most `BRIEF_LIMIT` characters). **The server calls no model**: `POST /api/sessions/{id}/reviews` (`routes/management.py`) makes a private session of the caller's (client `REVIEW_CLIENT`, server tag `review_of`, tag `review_prompt` with the prompt's title, traced) on a backend from `reviewers()` (the caller's own that serve OpenAI Chat, not `auth: agent`), and the console sends the brief through that session's agent endpoint, so limits, prices and recording apply as to any call. `reply()` reads a finished review back from its session's newest trace; `GET /api/sessions/{id}/review` lists the session's reviews the caller can view. A new check: a function in `CHECKS`, its name in `review_prompts.METRICS`, its row in `docs/session-review.md`. A new kind of data: a name in `review_prompts.DATA`, its function in `SECTIONS`, its row in the docs and in the YAML's comment. A new detector: an entry in `exposure.OWN`, `GENERIC` or `PERSONAL` (`DETECTORS` is `OWN` + `IMPORTED` + `GENERIC` + `PERSONAL`, most specific first; a later one skips what an earlier took), with a `check` that rejects placeholders and a `mask`, and its shape in `docs/session-review.md`. `IMPORTED` is built from `exposure_rules.py`, gitleaks' provider rules converted to Python by `devhelpers/scripts/secrets/import-gitleaks.py <tag>` (generated: rerun it, never edit it; it keeps gitleaks' MIT licence in its docstring); each runs only near its keywords (`_near`), which is what keeps 200 patterns cheap. `find(..., decode=True)` (`ScanLevel.decode`, standard and thorough) also reads the lines with escapes unescaped and base64 runs decoded (`_decoded`, one level deep); such a `Found` has an `encoding`, and `encoded` (the base64 run) is what `redact()` replaces. Tests: `test_review.py` |
| Cost estimates | `pricing.py`, `default_prices.yaml` | `DEFAULT_PRICES` (read from `default_prices.yaml`, the shipped table as data with its sources and the day they were checked; package data, so a wheel carries it; `test_pricing.py` fails for a row a wider one above hides), `checked_prices`, `price_for`, `estimate`, `total`. `Runtime._price` adds `cost` (or `unpriced`) to a record as it's finished, for hosted `api` backends (`basis: api`) and account or `anthropic` pass-through sessions (`basis: subscription`); never for a machine's model server. An `api` backend's own `prices` option (`api_providers.validate`) is tried first. The server's table is the `model_prices` setting (`Settings.prices`, `set_model_prices`; None means the shipped table), served at `/api/config/prices`; a session's sum at `/api/sessions/{id}/cost` (`routes/management.py`). `RequestTelemetry.cached_in_input` says cached tokens are inside the input count (OpenAI-style usage). An intercepted call is recorded under the host it went to, so `_price` takes `kind` `intercept`/`upgrade` as a subscription's. **Over time** (`costs.py`, `routes/costs.py`): `report(db, tenant, since, until, user)` reads the tenant's sessions active in the range (the `tenant` tag, filtered in Python: sessions have no tenant column) and their model calls (rows with tokens) and adds them up in all and by day, model, person (`launched_by`, else `owner`) and provider; `recompute` prices the same records again through `Runtime.reprice` (which keeps a removed provider's basis) and rewrites the changed `requests.record` rows in transactions of `CHUNK`; `Runtime.repriced` then updates this process's `recent` (another process's copy stays until it restarts: the database is right). Days are UTC, at most `MAX_DAYS`. Routes: `GET /api/orgs/{org}/costs` (`same_tenant`; `administers` sees everyone's, a member their own), `POST /api/orgs/{org}/costs/recompute` (`administers`, same origin; `ADMIN_ONLY` through `/api/orgs/*`), `GET /api/prices` (the table for anyone signed in). **Usage** (`analytics.py`): `usage(db, tenant, since, until, by, filters, user)` reads the same sessions and model calls and counts sessions, calls, cost, tokens and people in all, by day and by one dimension (`user`, `model`, `provider`, `agent`: the session's `client`), narrowed to one value of any of them; the `SERIES` busiest values get a series in each day and the rest are `OTHER`. Route: `GET /api/orgs/{org}/analytics` (in `routes/costs.py`, the same visibility as costs; a member's `user` filter is dropped). **In the session list**: a record's cost is also kept in `requests.cost_usd` and `requests.cost_basis` (`pricing.cost_columns`, written by `append_request`, `costs.recompute` and the legacy import; API step 10 added and filled them), so `SessionStore.usage()` sums every session's tokens, model calls and cost in the database for `GET /api/sessions/usage` (registered before `/api/sessions/{session_id}`). Anything that rewrites a record's `cost` must write these columns too. Tests: `test_costs.py`, `test_analytics.py` |
