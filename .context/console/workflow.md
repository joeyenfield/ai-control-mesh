# Console: extending, checking and docs

Part of [Console (`ui/`)](README.md). Adding to the console, checking changes visually, and writing `docs/` pages.

## Extending

- Start an agent (`pages/Agents.tsx`): two choices kept in the address (`?on=<machine id>&agent=<id>`; the last machine also in localStorage): where it runs ("Give me the command", or a machine with `you.launch`, each with `machineBlocker()`'s reason) and the agent, then `AgentStart` shows only that case: on a ready machine `Machine.tsx`'s exported `LaunchForm` with `initialAgent` and `fixedAgent` (no agent choice of its own); on one without the agent its `InstallCommand` for the machine's OS; for the command, the install command, then a collapsed **Install the agent command on that computer** (`OneLineInstall` with `only="agent"`, from `Downloads.tsx`; the same is on Your account and, as the **Only the agent command** choice of `INSTALL_CHOICES`, on Downloads) and `AccountCommand`/`ProxyCommand` with the extras under a collapsed Options. No machines you may launch on: a callout linking to `/machines#add`.
- **Page**: `pages/X.tsx` with the standard head (`header.page-head`: `<PartTag />`, the `<h1>`, or `.page-title` holding the `<h1>` and the page's actions, then a `p.lede` of one or two short sentences without commands; anything longer is a `p.subtle` or goes in the content), counts as `dl.stat-cards`, search in `.filters`, pill filters and toggles in `.chip-bar` (buttons with `aria-pressed`), top-level tabs as `TabBar className="page-tabs"`, and `p.empty` for empty and loading states. Sessions and Traffic are the models (Traffic's rows are `.traffic-list` buttons, not a table, so they fit beside the inspector). Running agents (`pages/Terminals.tsx`) is Sessions for the active ones: search and state chips over `.agent-list`, under the `AgentBar` header it shares with the Live agent view (`components/AgentBar.tsx`: the `grid-bar` with the running agents' counts, their summed cost from the same `["session-cost", id, "watch"]` queries as each row's `SessionCostPill`, and the **Open** dropdown to any running agent's terminal), whose rows (`AgentRow`) are links to the terminal, with the state from `terminalState()` and who, where and traffic from the `["terminals"]` summary (nothing worked out from requests). A list with details beside it (`.split`: Traffic, Requests) uses `components/DetailView.tsx`: `useDetailView(open)` gives `select(key)` (sets `?request=` and pushes a history entry marked `fromList`) and `close()` (Back when it came from the list, else it drops the parameter), and the page puts `detail-open` on `.page` with a `DetailBack` above the inspector. Below 1100px, where `.split` stacks, `detail-open` hides the head, cards and list so the details are the page, and the hook puts the list back where it was scrolled to (it follows `window.scrollY` while the list shows, since the page has already shrunk by the time an effect could read it). Running agents and the full-bleed terminal pages (`AgentBar`'s `grid-bar`, `term-bar`) and Docs (its Markdown has the title) are the deliberate exceptions. It also needs a `<Route>` in `App.tsx`, an entry in `PAGES` placed in one of `SECTIONS`, calls in `api.ts`, and docs in `docs/console.md`.
- **Provider view**: `MACHINE_TYPES`, `PROVIDERS`, the Settings `<option>` and `URL_PLACEHOLDERS`, a `<Kind>Provider` taking the props above, and its case in `ProviderView`. No global provider pages.
- Check with `npm run typecheck` and `npm run build`; for visual checks, the demo below.

## Checking changes visually

`python devhelpers/scripts/screenshots/demo.py` (which seeds five weeks of past sessions for five people of the demo team with `seed_history`, for Analytics and the session list; the demo user's own past sessions stay off the agents `capture.mjs` looks up by name, `qwen` and `claude-account`) runs a self-contained demo on :8199 (a direct intercept listener on :18199; no agent-proxy), in a temporary home with its own SQLite database seeded with `config_io.apply`, so the real `logs/` and database aren't touched. It has three made-up shared terminals fed through `FakeLauncher` (Claude Code at a permission prompt, OpenCode working, Codex finished; typing echoes back), three made-up machines over the fleet socket (`ai-desktop`, `ai-laptop`, `build-box`) whose provider requests `FakeProviders` answers and whose containers `FakeContainers` keeps in memory (`strata-iq3` ready, `strata-coder` waiting to switch in, `ollama-cpu`), fake backends (Ollama on :18434 and :18435, Anthropic on :18436, Docker Model Runner on :18437), seeded account sessions and live traffic. `--capture [names]` runs `capture.mjs` against it once the traffic is seeded, then stops it; prefer it, since a demo left running blocks the next one. It writes `.screenshot-demo.json` (its pid, its server's and issuer's, its folder) so `--stop` can stop one from another shell; Ctrl+C, SIGTERM and SIGBREAK all run the same cleanup (the `stopping` event first, so traffic and fake machines don't reconnect to a server going away).

`node devhelpers/scripts/screenshots/capture.mjs http://127.0.0.1:8199 docs/screenshots [name,...]` regenerates the screenshots in `docs/` (README and `docs/console.md`). It needs `playwright-core` and a browser; without Playwright's Chromium, pass one with `chromium.launch({ executablePath })` (on the dev computer, Edge at `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`). Keep throwaway screenshot scripts outside the repo. Update a screenshot when the page it shows changed visibly.

## Documentation pages (`docs/`)

The Contribute section includes `pipelines.md`, the Jenkins setup, branch/PR
verification, distribution testing and explicit release guide.

The Docs page (`/help`) renders `docs/*.md`. A new page goes into `DOC_SECTIONS` in `pages/Docs.tsx` (`test_help.py` checks every page is listed), the same section of `docs/index.md` (Start here, Use it, People and data, Run a server, Technical overview, Contribute). The guides (Start here to Run a server) are plain steps for users and operators; design, flows, protocols and internals go in Technical overview pages, so a guide links to them rather than carrying the detail and `README.md`'s table. Diagrams are Mermaid (`sequenceDiagram` for flows, `flowchart` for structure), never ASCII art. Headings: one H1, a handful of H2s, H3s only for genuinely separate parts, no H4s, no Contents lists; small topics are a paragraph with a bold lead-in, a list item or a table row. Plain short sentences, sentence case, saying what something does for the user.
