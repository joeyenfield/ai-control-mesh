# Console: server settings

Part of [Console (`ui/`)](README.md). The server settings pages.

## Server settings (`pages/Settings.tsx`, `pages/SettingsStored.tsx`)

- `pages/DeepSeekSetup.tsx` is the dedicated DeepSeek onboarding and ordinary edit form, used for preset ID `deepseek` and for saved providers the server marks `balance_supported`. It takes the existing server preset/fields unchanged for endpoints and protocols, asks for a key source plus optional name/team access, then saves and tests through the existing organization API. A check failure reports that the save succeeded, so retries do not create duplicate connections; a save failure keeps input available. Blank replacement keeps a vault key; switching to environment authentication sends `clear_key` when needed. Secrets are cleared after saving and kept only in local state before then. `ApiProviders.tsx` exposes a direct Connect DeepSeek tile, tailored saved-card labels, Refresh models and Claude guidance; Advanced settings retains `ProviderEditor` for full configuration. Styling is in the `.deepseek-*` rules in `styles.css`.

- API provider cards show `discovered_models` returned by automatic discovery, alongside aliases. Their listing query refreshes every five minutes while mounted. `balance_supported` from the server enables DeepSeek's **Check balance** button (disabled without a key), calling `api.apiProviderBalance(org, name)`. Its local mutation state shows availability and exact per-currency strings; balances are never polled or kept in shared query caches. Model discovery refreshes after five minutes; Test connection bypasses it and invalidates model queries. The discovery option explains this in the editor.

- `Settings.tsx` edits the network settings through `GET`/`PUT /api/config`: the listen address and URL, the **Public console address** (`proxy.public_url`; empty clears it), the default backend and hosted backends. `api` backends round-trip there as `{type, url}` (the server keeps their other options); their name, type and URL are read-only and they can't be removed there, only chosen as the default.
- The organization page's **API providers** tab (`Organization.tsx` `OrgDetail`, `?orgTab=providers`, for those who `manages` it; `pages/ApiProviders.tsx` `ApiProviderSettings({org})`) manages the organization's `api` backends through `/api/orgs/{org}/providers` (`["api-providers", org]`; `api.apiProviders`, `saveApiProvider`, `deleteApiProvider`, `testApiProvider`, each taking the org). The editor's **Teams that may use it** picks from `org.teams` (keys `<org>/<team>`); **Also share with** (`orgs`) shows only when the listing's `share` is true (site admins). Cards are grouped Hosted APIs / Gateways / On machines by `category`, with protocols, sign-in mode, where the key comes from (`has_key`, `key_source`; never the key), model aliases, priority and fallbacks, and health. Add from a preset or blank; the editor's key field is write-only (empty keeps the stored key, **Remove key** sends `clear_key`), and when `vault` is false it says a site admin uses `key_env` (`AI_PROXY_API_KEY_*`); the `key_env` field is disabled for anyone else, as the server keeps it from them. **Test connection** shows the result and offers to add the models it lists as aliases of themselves. Machine-hosted ones are added from the machine's page (adoption); their URL can't be changed. Saves invalidate everything, as adding a backend does.
- `SettingsStored.tsx` holds the sections for what used to be files, each a self-contained component: `AgentDefinitions` (every agent with a "Shipped", "Shipped, changed" or "Added here" badge, edited as YAML in `AgentEditor`; Reset for a changed shipped one, Add an agent, Remove), `ModelTuningEditor` (Ollama model tuning as one YAML document: defaults, profiles, aliases) `StorageSettings` (which database, its size, and the server's retention policy: `["retention"]` from `/api/config/retention`; saving also invalidates `["storage"]` and `["org-retention"]`) and `AuditSettings` (`["audit-config"]`: the key, backlog, checkpoint interval and exports; it refetches after saving, since `PUT` doesn't return the key or backlog). `components/ModelPrices.tsx` (`ModelPricesSettings`, the **Model prices** tab, `?tab=prices`) edits `["model-prices"]` (`/api/config/prices`) as rows the server checks; it exports `PriceRows`, `priceRow` and `pricesOf`, which `ProviderEditor` uses for a provider's own `prices`. Costs are never computed in the browser: a request's `cost` comes in its record (`RequestList`, `Inspector`), a session's total from `["session-cost", id, request_count]` (`/api/sessions/{id}/cost`), shown with `formatUsd`. `components/SessionCost.tsx` has `useSessionCost` (`["session-cost", id, "watch"]`, every 15 s) and `SessionCostPill`, used in the grid's tile headers (`TerminalTile`) and the terminal page's bar; Traffic adds up the costs of the rows shown, as it does their tokens. The Sessions list (`pages/Sessions.tsx`) shows each session's tokens and cost from `["sessions-usage"]` (`api.sessionsUsage`, every 30 seconds) in fixed-width columns (`.session-cols`), under a row of column names (`.session-columns`: an `xrow-head` with nothing to press, so it lays out as a row does; its margin makes up for a row's border), and sorts by them. Below 900px the columns become wrapping text with their units and the empty ones are hidden. `pages/Analytics.tsx` (`/analytics` for all four charts, `/analytics/<sessions|requests|cost|people>` for one, each a rail entry of the Analytics section; Usage has `end` so `sectionFor` and the rail don't take the pages under it for it) is an organization's usage as stacked bars: `["org-analytics", org, since, until, by, filters]` (`api.orgAnalytics`). Everything chosen is in the address (`org`, `since`, `until`, `by`, and a filter per dimension: `user`, `model`, `provider`, `agent`), so drilling down (`drill`: narrow to the picked value, split by the next dimension not narrowed) is a history step. `components/StackedChart.tsx` draws it (`StackedChart`, `SeriesLegend`; a series' colour is its `slot` in `--series-1` to `--series-8`, set for light and dark in `styles.css` from a palette checked for colour-blind separation, and `--series-other` for the rest; keep the order). `components/DayRange.tsx` is the organization and days control shared with Costs. `pages/Costs.tsx` (`/costs`, in Analytics as Costs and prices) is an organization's costs between two UTC days: `["org-costs", org, since, until]` (`api.orgCosts`; site admins pick the organization from `["orgs"]`), tabs in `?tab=` (Summary, Model prices, Recompute). Summary draws the server's sums with `components/CostChart.tsx` (`CostChart`: a bar a day in the shared `.chart` styles, money spent with the unbilled subscription part stacked on it as `.bar.unbilled`; `CostBars`: ranked rows by model, person and provider). Model prices is `ModelPricesSettings` for site admins (its `suggest` prop lists models used with no price, each added as a row; `onSaved` moves to Recompute) and a read-only table from `["prices"]` (`/api/prices`) for everyone else. Recompute (`api.recomputeCosts`, behind a `ConfirmDialog`) invalidates `["org-costs"]`, `["session-cost"]`, `["requests"]` and `["status"]`. `.table-scroll` is `position: relative` so a `visually-hidden` label in a wide table stays inside the scroller instead of widening the page. `components/SharedModels.tsx` (`SharedModelsSettings`, the **Shared models** tab, `?tab=shared`) edits `["shared-models"]` (`/api/config/shared-models`): the site's providers the server says can be shared, each with the models `useModels` knows plus typed ones; saving invalidates `["agents"]`, `["models"]` and `["providers"]`. `Settings.tsx` shows them as tabs kept in `?tab=` (the default tab stays mounted, so unsaved edits survive a switch). `retention.ts` holds the kinds' labels and day parsing shared with the Data tab; days are numbers or `null` (forever). They're admin-only on the server, so each hides itself on a 403 (`forbidden`) rather than showing an error.
- `ServerStats.tsx`'s "What the server keeps" table has a row for the database (`database: {kind, bytes}` from `/api/server/stats`) beside the folders. Its top is the live dashboard from the same answer's `live` (`ServerLive`): cards (`LiveNow`), the Traffic charts and `Technical` (facts, open WebSockets by kind, the server's processes when there's more than one). The server and machines send running totals (network bytes, requests answered, tunnel bytes); `rates.ts` `useRates(timestamp, totals, window)` turns successive samples into per-second series, leaving a gap rather than a spike when a total is missing or went backwards, and `ceiling()` gives those charts a top that follows the data. `Hosts.tsx` (`MachineLoad`, `MachineDetails`) uses the same for a machine's network and tunnel traffic; every `MachineSample` field after `gpu_error` is optional, since an older agent-machine doesn't send them.
- The YAML stays text in the browser: the server parses and validates it (`PUT` with a YAML body) and answers 400 with what's wrong. Don't parse or re-serialize definitions in the console.
