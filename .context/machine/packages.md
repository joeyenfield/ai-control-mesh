# Machine: command line and packages

Part of [Machine (`machine/`)](README.md). The `agent-machine` subcommands and the Go packages behind them.

## Command line (`internal/command`)

- `agent-machine` / `status`: show id, server, fleet state, providers, toggles, MCP servers, roots. `status --json` (`showJSON`, the `Status` struct; Python's `status_json`, same keys) is the short form for agent-tray: id, name, version, server, signed_in, user, running, state, pid, features (every toggle, through `Machine.Toggle`), roots, with no provider or container probing so it answers at once.
- `login [url] [--code CODE] [--enable LIST]`/`logout [url]` (OIDC device sign-in, `https://` when no scheme is given). `--code` (else `AI_PROXY_MACHINE_SETUP_CODE`) approves the device authorization with a console setup code at the issuer's `/device/setup` (`settings.ApproveWithSetupCode`, the endpoint checked by `IssuerEndpoint`) instead of a person, then polls `/token` at once; the code is never printed or logged. `--enable` (else `AI_PROXY_MACHINE_ENABLE`) switches toggles on after any sign-in (`settings.ParseToggles`, `terminals` = `commands`; checked before signing in, exit 2), with the same notes as `<toggle> on` (`Machine.ToggleNotes`). `run` and `start` call `login.Automatic` first: with the setup code set and no credentials for their server they sign in (start does it in the foreground, so a refused code fails start); either way they unset the variable so launches never inherit it; `run [--server url]` (foreground), `start` (detached, `AI_PROXY_MACHINE_STARTED=background`), `stop`.
- Toggles, all **off by default**: `launches`, `commands`, `files`, `updates`, `servers`, `containers` `on|off`; `containers cli auto|docker|podman`; `roots add|remove <dir>`; `name`; `address`.
- `config` (`internal/command/config.go`, Python `machine/config.py`) explains all six toggles and reads a comma-separated selection of names or numbers from stdin. A selection replaces the full toggle set; Enter preserves it, `none` clears it, invalid input retries, EOF cancels without saving permissions. It preserves identity, roots and other settings. No network or authentication is needed. The full-server installers invoke it through the terminal before machine sign-in, instead of enabling launches/files implicitly. Mirrored unit tests cover permission replacement, metadata preservation, invalid input and cancellation.
- `sudo agent-machine servers service [off]`: lets it drive a systemd `ollama.service` (a sudoers rule for `systemctl start|stop|restart ollama`, a drop-in, `/etc/agent-machine/ollama.env`).
- `mcp`, `mcp add <name> [--env] [--dir] [--description] -- <cmd...>` or `--url u [--header] [--description]`, `mcp remove`.
- `update [--force] [--server] [--with-agent]`, `version`.

## Packages

| Package | Responsibility | Key symbols |
| --- | --- | --- |
| `cmd/agent-machine` | Entry point, version from ldflags, cleans up old binaries | `main` |
| `internal/command` | The command line and status display, restart after an update | `Main`, `configure`, `run`, `start`, `stop`, `show`, `restartAfterUpdate` |
| `internal/presence` | The fleet connection: hello and updates, dispatching requests, tunnels, launches, shells, folders, the file viewer (`files.go`), remote update, provider detection | `Presence.Run`/`session`/`describe`, `DetectProviders`, `Check`, `CheckShell`, `Arguments`, `ShellArguments`, `AgentCommand`, `tunnelPorts`, `Folders`, `Files`, `RemoteUpdate` |
| `internal/providers` | Model-server operations and catalogue search, against fixed loopback paths | `Manager.Handle`, `ollama.go`, `llamacpp.go` (the router's `/models`: status, pull = `POST /models` with `/models/sse` progress, delete, load, unload; `llamaModelFiles`/`sizeFor`, which size a model the router names no file for by adding up its own `.gguf` files under `LlamaFolder()` and `LlamaCache()` (a bounded walk, every part of a split model together, `mmproj` left out, a quant in the name never matching another quant's files, read only when a model has no size); `LlamaServerPort`; `llamaPullBy`: `Request.Method` `""`/`router`/`direct`, falling back to a direct download when its own router answers 404 there, `noDownloads`), `api.go` (kind `api`, other OpenAI-compatible servers: status from `/v1/models` only), `llamacpp_files.go` (agent-machine downloading a model's GGUF files itself: `llamaPlanFor` from Hugging Face's tree, quant + shards + projector, into `LlamaFolder()/<repo>-<quant>/`; `.part` files, Range resume, SHA-256 against the LFS oid; `llamaServe` reloads, then `RestartLlama` once; ops `files` and `reload`; delete removes its own subfolders; only for `LlamaServerPort`), `strata.go`, `docker.go`, `Metrics`, `catalog.go` |
| `internal/servers` | Starting and stopping Ollama (only the one it started, or through systemd), llama.cpp and Strata profiles; Ollama's `OLLAMA_*` and llama.cpp's `LLAMA_ARG_*` settings, each a `table` (`settings_table.go`: settings, extra variables and what they may be, the file; values are one line). llama.cpp (`llamacpp.go`): `llama-server --host 127.0.0.1 --port <LlamaServerPort>` in router mode, the installed build first, else PATH, Termux or Homebrew; `llamacpp_install.go`: the install job (Termux's apt-get per variant, else the newest GitHub release's asset for the platform, `releaseVariants`/`variantOf`, SHA-256 against GitHub's digest, unpacked by `inside`-checked tar/zip into `llamacpp/<release>-<variant>/`, CUDA's runtime beside the binary, `prune` keeps the previous build); `llamacpp_settings.go` refuses host, port, keys, presets, CORS and anything naming TOOL, MCP, AGENT, SSL or PROPS, and always sets a GGUF folder (`LLAMA_ARG_MODELS_DIR`, default `llamacpp-models` in its folder, made before starting; its `init` points `providers.LlamaFolder` at it and `providers.LlamaCache` at its download folder `LLAMA_CACHE`, empty for llama.cpp's standard cache, which `providers` works out itself). presence wires `providers.Manager.RestartLlama` to this package's llama.cpp restart. With servers on, `strataState` syncs profiles to `strata models list --installed` (`syncProfiles`: `profile create` for each ready model no profile uses, named `freeName(id)`; never removes: only the console's remove/prune do, and only `broken` profiles not serving, as `removable` checks) and marks a profile whose run config file is gone `broken` (`configGone`), which `strataAction` won't start; an older Strata without `models list` falls back to the saved profiles | `Manager.Handle`, `ollama_settings.go`, `systemd.go` |
| `internal/containers` | Containers for the server: the engine table, spec checks, run arguments, the CLI, jobs | `Engines`, `Validate`, `RunArgsFor`, `Detect`, `Manager`, `Prefix = "ai-proxy-"` |
| `internal/mcp` | Shared MCP servers (`mcp.json`) and the bridge | `Server.Check`, `Load`/`Save`, `Bridge.Describe`/`ServeHTTP` |
| `internal/settings` | Its folder, credentials, `machine.json`, `status.json`, root checks; OAuth in `oauth.go` | `Home`, `Upstream`, `LoadMachine` (carries `agent-proxy/machine.json` over once), `Machine.Within`, `Status`, `Protocol`, `TokenHeader`, `DeviceLogin(server, setupCode, out)`, `ApproveWithSetupCode`, `SetupCodeEnvironment`, `AccessToken`, `TokenEnvironment`, `Toggles`/`ParseToggles`/`SetToggle`/`ToggleNotes` |
| `internal/login`, `update`, `process` | Sign-in (`Login`, `SignIn`, `Enable`, `Automatic`, `EnableEnvironment`); self-update from `/downloads/index.json` (SHA-256, `.old` swap); detached runs, `Stop`/`StopTree`, WSL-aware `LookPath` | |
