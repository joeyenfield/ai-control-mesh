What it looks at

Five areas and security, each with its own score.

A session can be tidy on tools and wasteful on context. Each area shows where the points went, and a separate security score flags credentials and personal data sent to the model.

Context

Is every call carrying too much? Large instructions, unused tools, a context that keeps growing.

Tools

Did the agent search, read and run commands efficiently, or repeat itself and fail?

How it went

Was the task clear? How much steering, how long, how many sub-agents?

Reliability

Calls that failed, were rate limited, were cut off or were slow to start.

Cost

Frontier models for everyday work, and prompt caching that ran out or was missed.

Security

Credentials, personal data and files of secrets the model was sent. Scored apart →

Secrets and personal data

What the model saw that it shouldn't have.

Agents read .env files, print the environment and paste customer data into their context. The review reads everything the model was sent and scores it apart: a leaked key isn't waste, and a tidy session can still leak one.

Credentials

Private keys, cloud and provider API keys, tokens, passwords in URLs, Authorization headers, and secrets in code and .env lines.

Personal data

Email addresses, phone numbers, card numbers that pass the Luhn check, US social security numbers and IBANs.

Files of secrets

A tool that read .env, id_rsa, *.pem or cloud credentials, or a command that printed every environment variable.

Where it came from

Typed into the chat, a tool call, a tool result or the instruction files, so you know what to block or ignore next time.
